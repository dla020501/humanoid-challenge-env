# Task C 채점기

과제 C의 평가 기준(`../README.md`)을 코드로 옮긴 것입니다. 상품 1개당 5개 항목 17점, 계산대 위 상품 3개를 처리하므로 총 51점 만점입니다. 시뮬레이션 루프 안에서 매 스텝 관측치를 받아 판정하며, 채점기는 로봇을 조작하지 않고 관측만 합니다.

| 파일 | 역할 |
| --- | --- |
| `taskc_scorer.py` | 5개 항목 판정, 중지 조건, 리포트 생성 |
| `geometry.py` | 해석적 최근접점(원통·박스), 회전 AABB, 띠 교차 |
| `qr_decode.py` | 스캐너 카메라 이미지 QR 판독 (예선·디코드·냉각) |
| `trace_write.py` | 재생 중 관측치를 프레임마다 기록 |
| `score_from_trace.py` | 기록된 관측치를 나중에 채점 |
| `check_trace.py` | 기록과 채점 결과가 서로 모순되지 않는지 자동 검사 |
| `selftest.py` | Isaac Sim 없이 도는 검증 35종 |

의존성은 Numpy 하나이며, Isaac Sim에 묶여 있지 않아 단독으로 실행할 수 있습니다.

---

## 1. 채점 판정 방식

| 항목 | 조건 | 배점 |
| --- | --- | --- |
| Sub 1-1 파지 | 그리퍼 모터 부하가 임계 이상으로 0.3초 연속 유지 | 2 |
| Sub 1-2 들어 올림 | 상품 AABB 최저점이 상판보다 20 mm 위 | 2 |
| Sub 2-1 스캐너 조준 | 쥔 상태 · 스캐너 프레임 점유 10% 이상 · 빔에서 0.15 m 이내를 1초 연속 | 3 |
| Sub 2-2 QR 인식 | 같은 3조건이 성립한 프레임에서 스캐너 이미지를 디코드해 기대 코드 일치 | 7 |
| Sub 3 띠 안 배치 | 내려놓은 순간 상품 AABB가 빨간 띠와 겹침 | 3 |

채점 로직은 두 가지로 분류됩니다.

1. **한 번이라도 달성 (Latch)**
* **평가 항목:** 파지, 들어 올림, 스캐너 조준, QR 인식
* **판정 기준:** 에피소드 진행 중 조건을 최초로 만족하는 순간 점수가 부여되며, 이후 상태가 바뀌어도 차감되지 않습니다. 동일 상품을 여러 번 처리해도 두 번째부터는 상태를 바꾸지 않으므로 점수가 오르지 않습니다.
* **연속 유지 조건이 붙은 항목(파지 0.3초, 조준 1초)은 한 프레임이라도 조건이 깨지면 타이머가 0으로 돌아갑니다.**

2. **내려놓은 그 순간 한 번 (State-check)**
* **평가 항목:** 띠 안 배치
* **판정 기준:** 쥔 상태가 풀리고 그 뒤 처음으로 상품 속도가 10 mm/s 미만이 된 시점의 상태를 한 번만 평가합니다. 이후 상품이 굴러 나가더라도 판정은 유지됩니다.
* QR 인식보다 먼저 띠 안에 놓은 것은 인정하지 않습니다.

> **평가 중지 조건 — 상품 3개가 모두 낙하한 경우**
> 계산대 위 상품 3개가 모두 바닥에 떨어지면 그 시점에 채점이 종료되고, 그때까지의 누적 점수가 최종 점수가 됩니다. 별도의 감점 제도는 없습니다.

> **판독 거리 제한 — 15 cm 밖에서 읽은 것은 인정하지 않습니다**
> 실물 스캐너의 인식 가능 거리가 15 cm이므로, 빔 출발선에서 상품 표면 최근접점까지 0.15 m를 벗어난 자리에서 읽힌 것은 점수로 인정하지 않습니다. 채점기는 이 조건이 성립한 프레임에서만 디코더를 호출하므로, 조건 밖의 프레임은 렌더 자체를 하지 않습니다.

## 2. Sub 1-1 파지 — 접촉 센서 대신 모터 부하로 판정합니다

이 로봇의 그리퍼는 액추에이터가 하나입니다(`gripper_master_l` → `gripper_l_joint1`). 좌우 손가락이 독립적으로 움직이지 않으므로 「양쪽 손가락이 동시에 닿았는가」를 따로 물을 수 없고, V홈에 물리든 팁에 물리든 그 모터의 부하 하나로 드러납니다. 평가표 원문의 의도(스친 것을 거르고 실제로 문 것만 인정)는 「0.3초 연속」 조건이 대신합니다.

```
부하 = clip(stiffness x (명령 - 실측), ±effort_limit)   [N·m]
FFW_SG2 좌측: stiffness 300.0, effort_limit 30.0, velocity_limit 2.2
```

판정은 두 조건을 동시에 봅니다.

```
① 부하 >= grip_load_min_nm                모터가 실제로 밀고 있는가
② (빈손 닫힘 q) - (실측 q) >= 여유          빈손보다 덜 닫혔는가 = 사이에 물체가 있다
   -> 둘 다 0.3초 연속
```

②가 헛집기를 거릅니다. 빈손으로 닫아도 관절 한계에 부딪혀 부하가 붙는 기구이므로, ①만으로는 허공을 쥔 것이 통과합니다. 빈손 닫힘 위치(`q_free_close`)를 실제로 재서 넣으면 그 구멍이 막힙니다. 넣지 않으면 ①만으로 판정하고 리포트의 `warnings`에 그 사실을 남깁니다.

### 실측 근거 (에피소드 8건)

`actions.npy`(명령)와 `joints.npy`(실측)의 `gripper_l_joint1`에서 뽑은 값입니다.

| 상품 | 정체 q | 명령 | 부하 |
| --- | --- | --- | --- |
| `chilsung_cider` | 0.976 | 1.10 | 30 (포화) |
| `cocacola_zero` | 1.028 | 1.10 | 30 |
| `pringles_original_small` | 0.790 | 0.98 | 30 |
| `pringles_sourcream_small` | 0.831 | 1.03 | 30 |
| `yegam_original` | 1.019 | 1.10 | 30 |
| `lotte_sand` | 1.047 | 1.10 | 30 |
| `samyang_buldak_cup` | 0.946 | 1.05 | 30 |
| `ottogi_cupnoodle_buldak` | 0.859 | 1.10 | 30 |

열림·대기 상태의 부하는 약 0 N·m이고 파지 중에는 30 N·m로 포화합니다. 정체 q는 0.790 ~ 1.047 범위이므로, 기본 임계 `grip_load_min_nm=5.0`은 열림과 파지 사이에 넉넉히 있습니다.

빈손 닫힘 위치는 **1.100021 rad**으로 측정했습니다(`task_c_replay.py --measure-q-free`). 8종 전부 같은 값이므로 한 번 재면 계속 사용하며, 채점 시 `--q-free-close 1.100021`로 넘깁니다. 가장 얇게 물린 `lotte_sand`(정체 q 1.047)도 여유 0.053으로 기본 임계 `grip_stall_margin_rad=0.02`를 통과합니다.

> 빈손 닫힘 측정은 채점할 판 안에서 하면 안 됩니다. 재는 동안 그리퍼를 열어야 하므로 그 판의 물리가 무너집니다(실측: 들어 올림 208 → 19 mm, QR 인식 3 → 0회). 별도 모드로 분리한 이유입니다.

## 3. Sub 2-2 QR 인식 — 스캐너 카메라 이미지로 판독합니다

평가 기준은 판독을 스캐너 카메라 이미지로 하도록 정하고 있습니다. 기하로 겨눔만 맞으면 되는 것이 아니라, 그 상품의 코드 문자열이 실제로 읽혀야 인정합니다. 실물 스캐너와 같은 시점이어야 하므로 다른 카메라는 사용하지 않습니다.

매 프레임 읽지는 않습니다. 800×500 렌더와 디코드가 비싸고, 실물 스캐너도 늘 읽고 있지 않습니다. 세 단계로 나눕니다.

| 단계 | 동작 |
| --- | --- |
| 기하 예선 | 기존 인식 조건에서 횡이탈 한계만 1.5배(6 → 9 mm)로 넓혀 대기합니다 |
| 이미지 판독 | 예선에 들어온 그 프레임만 스캐너 카메라를 렌더해 zxing으로 디코드합니다 |
| 냉각 | 한 번 읽히면 5초 동안 판독기를 끕니다. 예선을 벗어나도 끕니다 |

거리(50~250 mm)와 면 방향(cos ≥ 0.5) 조건은 넓히지 않습니다. 그 둘은 여유가 아니라 스캐너가 물리적으로 볼 수 있는 창이므로, 넓히면 볼 수 없는 자리에서 셔터를 누르게 됩니다.

카메라는 학습 데이터 수집 당시의 `ScanCam`을 그대로 옮겼습니다. 800×500, focal 31.43 mm, 조리개 20.955 / 13.097 mm이며, 눈은 빔 출발선 앞 3 cm, 겨눔점은 30 cm 앞입니다.

### 예선을 넓힌 이유

정답 궤적 시드 1의 두 번째 상품은 횡이탈 6.35 mm에서 읽혔습니다. 좁은 6 mm 기하 판정만 썼다면 발화하지 않았을 자리인데, 스캐너 이미지에는 코드가 온전히 찍혀 있었습니다. 기하는 겨눔의 근사이지 판독의 정의가 아니므로, 예선은 넓게 두고 읽혔는지는 이미지가 판정하도록 했습니다.

```
슬롯 0  t=23.5초   횡이탈 4.50 mm   거리 122 mm   8807531162229   판독 성공
슬롯 1  t=97.3초   횡이탈 6.35 mm   거리 151 mm   8803541964419   판독 성공
3000 프레임 중 디코드 시도 3회
```

### 관련 환경 변수

| 변수 | 기본값 | 의미 |
| --- | --- | --- |
| `TASKC_QR_IMG` | `1` | 이미지 판독 사용. `0`이면 기하 판정만 남습니다 |
| `TASKC_QR_GATE_MUL` | `1.5` | 예선 횡이탈 배율 |
| `TASKC_QR_COOLDOWN_S` | `5.0` | 판독 후 대기 시간 |
| `TASKC_QR_RENDER_N` | `8` | 디코드 직전 렌더 횟수 |

어느 방식으로 판정했는지는 `decode.json`의 `by` 필드에 `image` 또는 `geometry`로 기록되고, 읽힌 문자열은 `text`에 남습니다.

## 4. 채점기 연동

관측은 전부 콜백으로 받습니다. 특정 시뮬레이션 구현에 묶이지 않게 하기 위함입니다.

```python
from taskc_scorer import ScoreConfig, TaskCScorer

products = [dict(
    slug="cocacola_zero",
    shape="cylinder",                     # 또는 "box"
    radius=0.033, half_height=0.0615,     # cylinder
    # half_extents=(0.05, 0.03, 0.02),    # box 일 때
    axis_local=(0, 0, 1),
    expected_code="8804409121470",
    get_pose=lambda: (pos_xyz, quat_wxyz),
    get_lin_vel=lambda: vel_xyz,
), ...]

scorer = TaskCScorer(
    products, ScoreConfig(),
    table_z=measured_table_z,                  # 씬을 세운 뒤 재서 넣습니다
    band_rect=measured_band_rect,              # 마찬가지 (x0, x1, y0, y1)
    beam_origin_fn=lambda: beam_origin_xyz,
    grasp_fn=lambda slug: bool,                # 쥔 상태인가
    gripper_load_fn=lambda slug: load_Nm,      # 그리퍼 마스터 관절 부하
    gripper_pos_fn=lambda slug: q_grip_rad,    # 같은 관절 실측 위치
    q_free_close=1.100021,                     # 빈손 닫힘 위치 (측정값)
    in_frustum_fn=lambda slug: bool,           # 스캐너 프레임 점유
    decode_fn=lambda slug: "읽힌 문자열" or None,
)

while running:
    sim.step()
    scorer.tick(elapsed_seconds)
    if scorer.stopped:
        break

json.dump(scorer.report(), open("score.json", "w"), ensure_ascii=False, indent=1)
```

### 콜백이 지켜야 할 것

| 콜백 | 요구 사항 | 이유 |
| --- | --- | --- |
| `gripper_load_fn` | 그 상품을 쥔 손의 마스터 관절 부하를 반환 | 액추에이터가 하나라 이 값 하나로 충분합니다 |
| `q_free_close` | 빈손 닫힘을 실제로 재서 전달 | 넣지 않으면 헛집기를 거르지 못하며, 리포트에 경고가 남습니다 |
| `decode_fn` | 스캐너 카메라 이미지를 사용 | 실물 스캐너와 같은 시점이어야 합니다 |
| `decode_fn` | 거리 조건이 성립한 프레임에서만 렌더·디코드 | 렌더 비용 최적화가 아니라 채점 조건 그 자체입니다 |
| `table_z` `band_rect` | 씬을 세운 뒤 측정해서 전달 | 상수로 고정하면 안 됩니다. 상판은 놓이면 가라앉습니다 |

## 5. 리포트 형식

```json
{
 "elapsed_s": 42.5,
 "stopped": "③ 전 항목 획득",
 "config":   {"grip_load_min_nm": 5.0, "aim_dist_m": 0.15, "...": "..."},
 "measured": {"table_z": 0.9024, "band_rect": [0.1101, 0.4999, -0.01, 0.57]},
 "products": [
   {"slug": "cocacola_zero",
    "items": {"sub1_1_grip": {"pass": true, "pts": 2.0, "t": 3.51}, "...": "..."},
    "points": 17.0, "max": 17.0, "fallen": false, "notes": ["..."]}
 ],
 "total": 17.0, "max": 51.0
}
```

`config`와 `measured`를 함께 남기는 이유는, 나중에 점수만 보고 어떤 임계값으로 잰 것인지 되짚을 수 있어야 하기 때문입니다.

관측이 한 번도 들어오지 않은 항목은 0점(실패)이 아니라 `UNAVAILABLE`로 남습니다. 못 쟀다는 사실과 재서 떨어졌다는 사실을 구분하기 위함입니다.

```json
"sub1_1_grip": {"pass": "UNAVAILABLE", "pts": 0.0, "t": null}
```

## 6. 정답 궤적 채점 결과

동봉된 `gt` 3편을 전 길이로 재생해 채점한 결과입니다. `check_trace.py` 자동 검사는 세 판을 합쳐 142건이며 실패는 없습니다.

| `--seed` | 최종 점수 | 미획득 항목 |
| --- | --- | --- |
| **0** | 38.0 / 51 | 세 번째 상품(삼양 불닭 컵)의 조준·QR 인식·띠 안 배치 |
| **1** | 51.0 / 51 | - |
| **2** | 51.0 / 51 | - |

시드 0의 마지막 슬롯은 상품이 68.4 mm밖에 뜨지 못해 재현되지 않는 판이며, `docs/task_c.md` §5에 대조군으로 기록된 것과 같은 판입니다. 채점기가 이 실패를 그대로 걸러냅니다.

동일 상품을 여러 번 읽어도 점수는 오르지 않습니다. 시드 2에서는 삼양 불닭 컵 3회, 예감 오리지널 3회, 오뚜기 컵누들 불닭 2회가 실제로 판독됐지만 세 상품 모두 QR 인식 7.0점 그대로입니다.

> 프레임 상한에 주의하시기 바랍니다. `gt` 기록은 7567~9242줄이므로 `--frames`를 작게 주면 마지막 슬롯이 통째로 빠지고, 조준이 「빔까지 0.188 m」로 떨어집니다. 채점기 문제로 보이지만 기록이 잘린 것입니다.

## 7. 채점기 단독 실행 (Standalone)

Isaac Sim 구동 없이 Numpy 환경만 있으면 자체 검증을 실행할 수 있습니다.

```bash
python3 scripts/taskC/scorer/selftest.py      # 기하 수치·시나리오·규정 준수 35종
```

재생 결과를 채점할 때는 재생기에 `--trace`를 주어 관측치를 남긴 뒤, 기록을 채점합니다. 기록을 나중에 채점하므로 채점 규칙을 고칠 때 재생을 다시 돌릴 필요가 없습니다.

```bash
# 1) 재생하며 관측치를 기록합니다
python3 scripts/task_c_replay.py --set gt --seed 1 --headless \
    --trace out/trace --q-free-close 1.100021

# 2) 채점합니다
python3 scripts/taskC/scorer/score_from_trace.py \
    out/trace/trace.jsonl out/trace/scene.json out/trace/decode.json out/score.json

# 3) 기록과 채점 결과가 서로 모순되지 않는지 검사합니다
python3 scripts/taskC/scorer/check_trace.py out/trace
```

`check_trace.py`는 기록 자체의 무결성(30 Hz 간격, 로봇 좌표계, 빔 방향 단위벡터, 슬롯 범위)과 채점 결과의 정합성(처리하지 않은 상품이 0점인지, 읽었으면 들었는지, 놓았으면 읽었는지, 상품별 파지 시각이 서로 다른지), 그리고 QR 판독 규칙(이미지로 판독했는지, 예선 안에서 읽었는지, 냉각을 지켰는지)을 검사합니다.

| 총점 표기 | 미확정 | 상품당 17점으로 3개면 51점이나, 원본 시트의 합계 수식은 Sub 3을 제외해 14점입니다 |

Sub 2-1의 「프레임 점유 10% 이상」은 `score_from_trace.coverage()`가 스캐너 카메라를 해석적으로 재현해 상품 OBB 8꼭짓점을 투영하고 화면과 겹치는 넓이 비율로 계산합니다. 그런데 실측값이 100%로 포화합니다. 스캐너 카메라의 수평 화각이 약 37도인데 제시 순간 상품이 카메라에서 수 cm 거리라 프레임을 완전히 넘치기 때문입니다. 판독 거리 안에 들어오면 이 조건은 자동으로 충족되므로, 실질적으로 거르는 것은 상품이 카메라 뒤에 있거나 시야 밖일 때뿐입니다. 또한 OBB 투영이라 가려짐을 반영하지 못하고 원통을 상자로 근사하므로, 이 값은 실제 점유율의 상한입니다. 픽셀 단위로 정확히 재려면 스캐너 카메라에 인스턴스 세그멘테이션을 켜야 하며, 렌더 비용이 오르므로 현재는 적용하지 않았습니다.

*평가 항목별 임계값은 `taskc_scorer.py`의 `ScoreConfig`에, 평가 기준 원문과 미확정 항목은 `EVALUATION_DRAFT.md`에 있습니다.*
