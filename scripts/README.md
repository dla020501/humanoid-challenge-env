# scripts/ — 데모 및 실행 스크립트

이 스크립트들은 도커 컨테이너의 `/workspace/challenge_scripts` 디렉터리에 마운트됩니다. 컨테이너를 다시 빌드할 필요 없이 `git pull` 명령어만으로 최신 코드를 반영하여 실행할 수 있습니다.

| 파일명 | 기능 설명 |
| --- | --- |
| `task_a_demo.py` | **과제 A의 초기 환경(장면)**을 생성하여 렌더링합니다. |
| `task_b_demo.py` | **과제 B의 초기 환경(장면)**을 생성하여 렌더링합니다. |
| `task_b_replay.py` | **과제 B의 시연 기록 전체**를 처음부터 끝까지 재생합니다. |
| `task_c_demo.py` | **과제 C의 초기 환경(장면)**을 생성하여 렌더링합니다. |
| `task_c_replay.py` | **과제 C의 시연 기록**(상품 3개 연속 처리 또는 단일 상품)을 물리 엔진 기반으로 재생합니다. |
| `taskA/` | 과제 A의 **환경 정의 모듈 및 실측 데이터**가 포함되어 있으며, 데모 스크립트가 이를 참조합니다. |
| `taskB/` | 과제 B의 **채점기**(`taskb_score.py`)와 `task_b_replay.py`에서 사용하는 **시연 기록 7세트**(`demos/`, 2.4 MB)가 포함되어 있습니다. |
| `taskC/` | 과제 C의 **환경 정의 모듈**, `task_c_replay.py`에서 사용하는 **시연 기록**(`demos_gt/` 3세트 · `demos/` 8세트, 9 MB), 그리고 **채점기**(`scorer/`)가 포함되어 있습니다. |

### 코드 및 에셋 구조

과제 A의 환경을 구성하는 코드는 아래 폴더에 정리되어 있습니다.

```text
scripts/taskA/
  taskA_seats.py        12개의 시식 좌석 좌표 — 로봇의 대기 위치와 바구니의 시작 위치
  taskA_layout.py       목표 진열대, 인접한 책상의 위치 및 로봇의 초기 자세
  taskA_stools.py       스툴을 로봇 좌석의 반대편으로 이동시키는 로직
  taskA_colliders.py    매장 집기의 충돌체(Collider) 활성화 (원본 USD에는 비활성화되어 있음)
  taskA_robot_pose.py   로봇의 기립 자세 설정
  eatin_measured.json   시식 코너의 실측 데이터 (좌석 좌표 산출용)
  destinations.json     목적지 및 책상 좌표 데이터

```

코드에는 정책(Policy) 모델이 마주하게 될 환경이 어떻게 구성되는지 상세히 정의되어 있으며, 이 내용은 `git pull`을 통해 지속적으로 업데이트됩니다.

**에셋 파일은 배포된 도커 이미지 내부에 포함되어 있습니다.** 매장 USD(200 MB), 로봇, 각종 집기 등은 용량이 크고 94개의 상대 경로 참조를 포함하고 있어 통째로 관리되어야 합니다. 따라서 **이 저장소의 코드와 도커 이미지가 모두 준비되어 있어야 정상 작동**합니다. 사용할 이미지 주소는 `docker/.env` 파일의 `CHALLENGE_IMAGE` 항목에 명시되어 있습니다. (과제 A 및 C의 환경 정의 코드를 별도 저장소로 분리한 이유는 대용량 매장 에셋과 분리하여 관리하기 위함입니다.)

## `task_a_demo.py`

```bash
# 도커 컨테이너 내부에서 실행
cd /workspace/cyclo_lab
${ISAACLAB_PATH}/_isaac_sim/python.sh -u \
    /workspace/challenge_scripts/task_a_demo.py --seed 1000

```

시뮬레이션 창이 열리고 **과제 A 에피소드의 시작 환경**이 렌더링된 상태로 대기합니다. 로봇은 추가적인 동작(집기, 주행, 놓기 등)을 수행하지 않으며, 사용자의 정책 모델이 받게 될 첫 번째 관측(Observation) 상태를 시각적으로 확인하기 위한 데모입니다.

### 환경 구성 요소

* **매장 환경:** 편의점 전체 구조(통로, 곤돌라, 냉장고, 냉동고, 와인 진열대, 계산대, 시식 코너)가 로드됩니다. 과제 B와 달리 과제 A는 **매장 전체를 가로지르는 주행**이 포함됩니다. (목적지 직선거리 9.3 ~ 11.2m, 실제 주행 경로는 더 김)
* **시식 탁자와 좌석:** 원형 탁자 3개를 4등분한 **12개의 고정 좌석** 중 한 곳에서 로봇이 출발합니다. 로봇은 좌석 위치에서 탁자 쪽으로 300mm 전진한 위치(탁자 중심에서 0.624m)에 서게 됩니다. 이 위치에서는 탁자와의 거리 제한(0.805m 미만)으로 인해 **제자리 회전이 불가능**하며, 물체를 집은 후 뒤로 물러나야 회전할 수 있습니다.
* **바구니 (파란 상자):** 탁자 위에 놓이는 파란색 상자(0.380 × 0.590 × 0.140 m)로, 로봇을 향해 긴 면이 놓이도록 배치됩니다.
* **스툴:** 해당 탁자의 스툴 4개는 로봇의 **반대편으로 강제 이동**됩니다. 시드에 따라 스툴의 초기 각도가 다르기 때문에, 로봇의 회전 반경(0.55m 이상)을 확보하기 위해 치우는 과정이 포함됩니다.
* **목표 진열대와 책상:** 도착지점인 목표 진열대 앞의 좌표와 바구니를 올려놓아야 할 책상의 위치가 지정됩니다. 환경 내 책상은 단 하나만 존재합니다.
* **로봇 (초기 자세):** 로봇의 몸통(Torso)은 작업 높이(-0.060)로 하강하고, 머리는 39.8도 숙인 채로 집기 동작 직전의 자세를 취합니다. **바퀴는 바닥에 정확히 닿아 있으며**, 스크립트 실행 시 실제 측정된 바퀴 높이 값이 로그로 출력됩니다.
* **카메라:** 채점기에 전송되는 카메라는 총 3대입니다. 머리 `head_l`(672×376, 실기 ZED 좌안) 및 양 손목 `wrist_l`/`wrist_r`(424×240, D405).

> 주행용 관측 데이터(LiDAR `scan`)는 추후 별도의 마일스톤을 통해 추가될 예정입니다.

### Seed 값에 따른 환경 결정 규칙

동일한 `--seed` 값을 입력하면 항상 완전히 동일한 환경이 생성됩니다. Seed 값은 아래 4가지 요소를 결정합니다.

| 변경 요소 | 설명 | 결정 규칙 |
| --- | --- | --- |
| **좌석 위치** | 12개의 좌석 중 로봇과 바구니의 출발 위치 | `(seed × 7919) % 12` |
| **목표 진열대** | 21개의 상품 배치 및 앞줄의 빈 공간 3칸 위치 | seed 값에서 도출된 진열대 시드 |
| **기타 진열대** | 12개의 곤돌라에 배치되는 상품 | seed 값에서 도출된 매장 시드 (12개 프리셋 중 1개) |
| **기타 스툴** | 로봇이 사용하지 않는 나머지 두 탁자의 스툴 8개 위치 | seed 값 |

**진열대와 냉장고 등 주요 집기의 위치는 고정되어 있습니다.** 내부 선반에 배치되는 상품의 종류와 위치만 변경되며, 장애물의 형태가 시드의 영향을 받지 않기 때문에 충돌 판정 역시 고정된 로직을 따릅니다.

기타 진열대 배치는 런타임 계산이 아닌 **사전 렌더링된 12개의 프리셋**(`taskA/stores/`) 중 하나를 불러오는 방식을 사용합니다. 이는 진열 생성기의 부동소수점 연산이 CPU 아키텍처에 따라 미세한 차이를 발생시키는 현상을 방지하여 완전한 재현성을 보장하기 위함입니다. 목표 진열대는 `taskA/taskA_shelf_stock.py` 스크립트를 통해 계산되며, 이는 과제 B의 로직을 과제 A 좌표계로 변환한 것입니다.

### 실행 옵션

| 옵션 | 설명 |
| --- | --- |
| `--seed N` | 환경 난수 시드 (기본값: 1000) |
| `--seat {0..11}` | 좌석 번호를 수동으로 지정합니다. 지정하지 않으면 시드 기반으로 결정됩니다. |
| `--seconds S` | 시뮬레이터를 S초 동안 실행 후 종료합니다. (0 입력 시 수동 종료 대기) |
| `--headless` | 시각적 렌더링 화면 없이 백그라운드에서 실행합니다. |
| `--scene-json FILE` | 생성된 환경 정보를 지정한 경로에 JSON 파일로 저장합니다. |
| `--shot FILE.png` | 로봇의 머리 카메라(`head_l`) 시점의 이미지를 한 장 캡처하여 저장합니다. |
| `--check` | **좌석 기하구조, 상품 진열, 매장 USD 로드 상태만 검사하고 즉시 종료합니다.** 시뮬레이터를 띄우지 않아 1초 내외로 완료됩니다. |

### `--check` 옵션을 통한 빠른 검증

시뮬레이터를 로드하는 데 시간이 소요되므로, 좌석이 벽에 겹치거나 스툴 배치가 회전을 방해하는 등의 기하학적 오류를 사전에 빠르게 확인할 수 있습니다. 오류 발생 시 `판정:` 항목 아래에 `!` 기호와 함께 원인이 출력되며, 프로세스는 종료 코드 1을 반환합니다.

### 데이터 및 이미지 추출 방법

**장면 정보를 JSON으로 저장하기:**

```bash
${ISAACLAB_PATH}/_isaac_sim/python.sh -u \
    /workspace/challenge_scripts/task_a_demo.py --seed 1000 --headless \
    --seconds 1 --scene-json /workspace/user/scene_a_1000.json

```

**헤드리스 모드에서 카메라 이미지 캡처하기:**

```bash
${ISAACLAB_PATH}/_isaac_sim/python.sh -u \
    /workspace/challenge_scripts/task_a_demo.py --seed 1000 --headless \
    --seconds 1 --shot /workspace/user/shot_a_1000.png

```

### 좌표계 안내

* 바닥면: `z = 0`
* 매장 범위: `x` (-11.1 ~ 1.3), `y` (-5.12 ~ 7.25)
* 주행 통로 방향: **Y축 방향**
* 시식 코너는 서쪽(-X), 목표 진열대는 동쪽(원점 부근)에 위치하므로 로봇은 서쪽에서 동쪽으로 주행하게 됩니다.

```bash
# 도커 컨테이너 내부에서 실행
cd /workspace/cyclo_lab
${ISAACLAB_PATH}/_isaac_sim/python.sh -u \
    /workspace/challenge_scripts/task_a_replay.py --seed 6

```

### 포함된 시연 기록

총 3개의 시연 기록이 제공되며, 모두 채점 기준 만점(21/21)을 달성한 데이터입니다. `--list` 옵션으로 시뮬레이터 로드 없이 즉시 목록을 확인할 수 있습니다.

| `--seed` | 좌석 | 총 프레임 | 재생 시간 | 점수 | 구간별 프레임 (집기/주행/놓기) |
| --- | --- | --- | --- | --- | --- |
| 0 | 0 | 1473 | 147 초 | 21 / 21 | 170 / 1034 / 269 |
| 2 | 10 | 1353 | 135 초 | 21 / 21 | 170 / 911 / 272 |
| 6 | 6 | 1893 | 189 초 | 21 / 21 | 170 / 1449 / 274 |

이 스크립트에서 `--seed` 값은 **환경을 구성하는 동시에 재생할 시연 기록 번호**를 의미합니다. 시연 과정은 크게 3구간(집기, 주행, 놓기)으로 나뉘며 현재 진행 중인 구간이 터미널에 실시간으로 출력됩니다.

### 기구학(Kinematic) 기반 재생 방식

재생 방식은 물리 엔진의 연산을 따르지 않고, 매 프레임마다 기록된 31개의 관절 각도, 베이스 좌표, 바구니의 자세 값을 **강제로 덮어쓰는 방식**으로 작동합니다.

*원본 기록은 GPU 기반의 물리 연산 및 컴플라이언트(Compliant) 바닥 환경에서 10 FPS로 수집되었습니다. 본 데모는 CPU 물리 연산 환경이므로, 긴 주행 시간 동안 누적되는 물리 연산 오차로 인한 바구니 떨어짐 현상을 방지하기 위해 강제 할당 방식을 채택했습니다.*

**재생 시 필수 검증 항목 (코드 자동 검사):**

1. **관절 이름 매핑:** 시연 기록의 관절 데이터(19개)와 베이스 휠(6개)을 실제 모델의 31개 관절 이름과 정확히 매핑합니다.
2. **그리퍼 동기화:** 2~4번 그리퍼 마디의 값을 1번 마디의 값으로 매 프레임 동기화하여, 허공을 쥐는 현상을 방지합니다.
3. **루트 쿼터니언 변환:** 자세 제어 시 로봇이 측면으로 눕지 않도록, 기록된 수직축 기반 쿼터니언 데이터를 월드 좌표계에 맞게 변환하여 적용합니다.

**물리 접촉 미구현:**
자세를 강제로 덮어쓰기 때문에, 그리퍼가 바구니를 누르거나 미끄러지는 등의 실제 물리적 마찰 및 상호작용은 렌더링 화면에 표현되지 않습니다. (다만 3개의 시연 기록 모두 실제 환경에서 성공 검증을 마친 데이터입니다.)

### 재생 중 실시간 채점 및 단독 실행

과제 A의 채점 로직(6개 항목, 총 21점)이 백그라운드에서 구동되며, 각 주행 구간이 끝날 때마다 터미널에 점수가 출력됩니다. 시각적 오차를 방지하기 위해 점수는 실시간 렌더링 화면이 아닌 **원천 데이터(`.npz` 파일)를 기반으로 사전 계산**됩니다.

시뮬레이터 없이 numpy 데이터만으로 단독 채점도 가능합니다.

```bash
# 호스트 PC에서 실행
python3 scripts/taskA/scorer/taska_score.py scripts/taskA/demos/demo_00.npz

```

*채점은 힘 센서가 아닌 기하학적 좌표(손가락 끝이 바구니 표면 40mm 이내, 두 손가락 간격 60mm 이내 등)를 기준으로 판정하며, 이는 힘 기반 판정과 99.9% 일치함이 검증되었습니다.*

### 실행 옵션

| 옵션 | 설명 |
| --- | --- |
| `--seed N` | 재생할 시연 기록 번호 지정 (0, 2, 6 중 선택 / 기본값: 6) |
| `--list` | 시뮬레이터 실행 없이 포함된 기록 목록만 출력 |
| `--substeps N` | 프레임 간 보간을 위한 분할 횟수 (기본값: 4). 숫자가 클수록 부드럽지만 느려짐 |
| `--hz H` | 초당 화면 렌더링 프레임 수 (기본값: 40). 0 입력 시 제한 없음 |
| `--from_seconds S` | 지정된 S초 시점부터 렌더링 시작 |
| `--as_recorded` | 진열대 상품 배치를 **데이터 수집 당시와 동일하게** 구성하여 렌더링 |
| `--headless` | 시각적 화면 렌더링 없이 백그라운드 실행 |

## `task_b_demo.py` & `task_b_replay.py`

과제 B 환경은 특정 진열대 하나를 대상으로 진행됩니다.

### 초기 환경 생성 (`task_b_demo.py`)

지정된 5단 진열대에 상품이 채워지고, 2단과 3단의 앞줄 중 일부가 비워집니다. 빈 공간에 채워넣어야 할 상품은 책상 위 파란색 상자 안에 배치됩니다. 로봇은 상자를 마주 보고 정렬하며, 초기 시야에 진열대는 포함되지 않습니다.

**코드명 및 영문명 분리 관리:**
과제 B와 C의 상품은 시스템 내부적으로 처리하기 위한 **내부 코드명**(예: `pringles_original_small`)과 로봇 지시문에 사용되는 **표시용 영문명**(예: `small original Pringles tube`)으로 나뉘어 관리됩니다.

**Seed 및 빈 칸 조절:**

* `--gaps`: 진열대에 비워둘 칸의 개수 (1~3개, 기본값 1). 숫자가 늘어날수록 로봇이 수행해야 할 배치 작업 횟수가 증가합니다.
* `--seed`: 난수 시드 값. 동일한 gaps와 seed를 입력하면 항상 같은 상품과 위치가 생성됩니다.

### 시연 기록 재생 (`task_b_replay.py`)

사전 수집된 7개의 성공 시연 궤적을 재생합니다. 과제 A와 마찬가지로 물리가 아닌 기하학적 자세 덮어쓰기 방식으로 작동합니다.

* `--seed`: (0~6) 범위의 값을 입력하여 재생할 시연 기록을 선택합니다.
* 재생 중 15개 평가 항목(34점 만점)에 대한 실시간 채점 결과가 출력됩니다. 채점 로직 중 바닥에 상품이 떨어지면 그 즉시 해당 상품의 채점 프로세스가 중지됩니다.

## `task_c_demo.py` & `task_c_replay.py`

과제 C는 편의점 매장의 계산대를 배경으로 하며, 로봇은 주행하지 않고 정지 상태에서 작업을 수행합니다.

### 초기 환경 생성 (`task_c_demo.py`)

계산대 상판 지정된 붉은색 띠 내부에 3개의 상품이 스폰됩니다. 스폰되는 상품은 설정된 물리 규칙(QR면 노출 방향, 최소 간격 유지, 원통 직립 등)을 준수할 때까지 최대 50회 재배치됩니다. 주변의 정적 바구니 및 하단 선반 등은 로봇 간섭을 막기 위해 비활성화됩니다.

* `--seed`: 무작위 상품 3종과 배치 형태를 결정합니다. (**0, 1, 2번 시드**는 주최 측 평가 표본 데이터가 고정되어 있습니다.)
* `--products a,b,c`: 상품 3종을 수동으로 지정할 수 있으며, 첫 번째 상품이 로봇의 조작 대상이 됩니다. 위치는 시드에 의해 자동 결정됩니다.

### 시연 기록 물리 재생 (`task_c_replay.py`)

과제 C의 시연 재생은 과제 A, B와 달리 **물리 엔진 기반 재생 방식**을 사용합니다. 기록된 관절 명령(actions)을 로봇에게 프레임별로 인가하고, 시뮬레이터 내부의 물리 엔진이 상품과의 상호작용 및 움직임을 직접 연산합니다.

* `--set gt`: 3개의 상품을 연속 처리하는 평가 표본 데이터 재생
* `--set single`: 8종의 단일 상품별 훈련 데이터 재생
* 실시간 관측 데이터를 기반으로 5항목 17점 만점의 채점기(`scorer/`)를 연동하여 시뮬레이션 판정을 수행할 수 있습니다. 자체 검증 모듈(`selftest.py`)이 포함되어 있습니다.
